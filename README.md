# Telegram-бот подписки на закрытый канал (Telegram Stars)

Бот продаёт доступ к закрытому каналу на **1 месяц** и **3 месяца**, принимает оплату в **Telegram Stars (XTR)**, автоматически выдаёт персональную инвайт-ссылку и **удаляет пользователя из канала** по истечении подписки.

Техническое задание: [TZ-telegram-subscription-bot.md](TZ-telegram-subscription-bot.md)

## Что умеет

- Два тарифа: 1 месяц и 3 месяца (цена и срок задаются в `.env`).
- Оплата в Telegram Stars — без карт, эквайринга и юрлица.
- Персональная одноразовая инвайт-ссылка сразу после оплаты.
- Продление суммирует срок: дни добавляются к текущей дате окончания.
- Напоминания за 3 дня и за 1 день до окончания.
- Автоматическое удаление из канала по истечении срока (с возможностью вернуться после продления).
- Админ-команды: статистика, карточка пользователя, ручная выдача и отзыв доступа.
- Устойчивость: повторная доставка платёжного события не продлевает подписку дважды.

## Требования

| Что | Версия |

## Пошаговый запуск

### Шаг 1. Скопировать проект и создать окружение

Откройте терминал в папке проекта.

**Windows (PowerShell или cmd):**

```bat
cd C:\путь\к\проекту
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

**Linux / macOS:**

```bash
cd /путь/к/проекту
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

После активации в начале строки появится `(.venv)`. Все следующие команды выполняются в активированном окружении.

### Шаг 2. Создать бота и получить токен

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте `/newbot`.
3. Придумайте имя бота (отображается пользователям) и username (должен заканчиваться на `bot`).
4. BotFather пришлёт токен вида `1234567890:AAH...` — это `BOT_TOKEN`.

> Токен — пароль от бота. Никому его не передавайте и не публикуйте.

Для приёма Stars **не нужно** подключать платёжного провайдера: используется `currency=XTR` с пустым `provider_token`.

### Шаг 3. Создать закрытый канал

1. В Telegram: «Создать канал» → укажите название.
2. Тип канала — **закрытый** (Private). Важно: в закрытый канал нельзя войти по публичной ссылке, только по инвайту.
3. Если хотите вручную одобрять заявки — включите «Заявки на вступление» (бот их обрабатывает). Для автоматического входа по ссылке заявки лучше **выключить**.

### Шаг 4. Выдать боту права в канале

1. Откройте канал → «Управление» → «Администраторы» → «Добавить администратора».
2. Найдите своего бота по username и добавьте.
3. Включите права:
   - ✅ **Приглашать по ссылке** (`can_invite_users`) — обязательно, иначе бот не создаст ссылку;
   - ✅ **Блокировать участников** (`can_restrict_members`) — обязательно, иначе бот не сможет удалять по истечении срока.

Остальные права не нужны.

### Шаг 5. Узнать CHANNEL_ID

Нужен числовой ID вида `-1001234567890`.

**Способ А — через бота-помощника (проще всего):**

1. Перешлите любое сообщение из вашего канала боту [@getidsbot](https://t.me/getidsbot).
2. Бот ответит карточкой канала, где будет `ID: -100...`. Скопируйте это число.

Альтернативы: [@userinfobot](https://t.me/userinfobot), [@username_to_id_bot](https://t.me/username_to_id_bot).

**Способ Б — через API:**

1. Временно сделайте канал публичным или отправьте в него сообщение от своего имени.
2. Откройте в браузере:
   ```
   https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
   ```
3. Найдите в ответе `"chat":{"id":-100...}` — это `CHANNEL_ID`.

> У каналов ID всегда отрицательный и начинается с `-100`.

### Шаг 6. Узнать свой Telegram ID

Свой личный ID нужен для `ADMIN_IDS` (доступ к админ-командам).

1. Запустите бота (шаг 8) — пока можно без `CHANNEL_ID`, бот стартует и предупредит в логе.
2. Напишите боту `/myid` — он пришлёт ваше число.
3. Впишите его в `.env` в `ADMIN_IDS` и перезапустите бота.

Либо заранее: напишите [@userinfobot](https://t.me/userinfobot) — он покажет ваш `Id`.

Несколько админов указываются через запятую: `ADMIN_IDS=111111111,222222222`.

### Шаг 7. Заполнить .env

Скопируйте шаблон и откройте его в любом редакторе.

**Windows:**

```bat
copy .env.example .env
notepad .env
```

**Linux / macOS:**

```bash
cp .env.example .env
nano .env
```

Минимально нужно заполнить три строки:

```env
BOT_TOKEN=1234567890:AAH...ваш_токен
CHANNEL_ID=-1001234567890
ADMIN_IDS=123456789
```

Полный список параметров — в разделе [переменные окружения](#переменные-окружения).

> Файл `.env` уже добавлен в `.gitignore` — в git он не попадёт.

### Шаг 8. Запустить бота

```bash
python -m bot.main
```

Что должно быть в логе при успешном старте:

```
INFO | __main__ | Канал готов к работе
INFO | __main__ | Бот запускается (polling)
INFO | aiogram.dispatcher | Run polling for bot @your_bot id=... - 'Имя бота'
```

Если появилось `⚠️ Бот запущен, но канал не готов` — вернитесь к шагу 4 (права) или шагу 5 (`CHANNEL_ID`).

Остановить бота — `Ctrl+C`.

Бот работает через long polling: домен, HTTPS и белый IP не нужны.

### Шаг 9. Проверить работу

1. Откройте своего бота по ссылке `https://t.me/<username_бота>` и нажмите «Запустить».
2. Должно прийти приветствие и список тарифов.
3. Отправьте `/check` — ответ «✅ Бот готов к работе».
4. Отправьте `/admin` — должна открыться админ-панель (если ваш ID в `ADMIN_IDS`).
5. Тестовая покупка: «💳 Купить подписку» → тариф → оплата Stars → бот пришлёт кнопку «Войти в канал».
6. Вступите по ссылке — бот подтвердит активацию и покажет дату окончания.
7. Проверьте `/stats` и `/user <ваш_id>` — платежи и подписка должны отображаться.

> Тестовые Stars списываются реально. Для проверки без трат можно выдать доступ вручную: `/grant <ваш_id> m1` — бот создаст подписку, а ссылку можно получить кнопкой «Получить ссылку на канал» в «Моя подписка».

## Переменные окружения

| Переменная | Обязательно | По умолчанию | Описание |
|---|---|---|---|
| `BOT_TOKEN` | да | — | токен от @BotFather |
| `CHANNEL_ID` | да | — | ID закрытого канала, `-100...` |
| `ADMIN_IDS` | да | — | Telegram ID админов через запятую |
| `CHANNEL_TITLE` | нет | `закрытый канал` | название канала в текстах бота |
| `CHANNEL_PUBLIC_LINK` | нет | — | публичная ссылка канала (только для текстов) |
| `INVITE_TTL_HOURS` | нет | `24` | сколько часов живёт инвайт-ссылка |
| `GRACE_HOURS` | нет | `0` | льготный период после окончания; `0` — кик сразу |
| `REMINDER_DAYS_1` | нет | `3` | первое напоминание, за N дней |
| `REMINDER_DAYS_2` | нет | `1` | второе напоминание, за N дней |
| `PLAN_1M_DAYS` | нет | `30` | срок тарифа «1 месяц» |
| `PLAN_1M_STARS` | нет | `300` | цена тарифа «1 месяц» в Stars |
| `PLAN_3M_DAYS` | нет | `90` | срок тарифа «3 месяца» |
| `PLAN_3M_STARS` | нет | `750` | цена тарифа «3 месяца» в Stars |
| `TIMEZONE` | нет | `Europe/Moscow` | часовой пояс в сообщениях |
| `LOG_LEVEL` | нет | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR` |
| `DATABASE_URL` | нет | SQLite `data/bot.db` | строка подключения к БД |

Тарифы перечитываются из `.env` при каждом старте: изменили цену — перезапустите бота, существующие подписки не затрагиваются.

**PostgreSQL** (для нагрузки от нескольких тысяч пользователей):

```bash
pip install asyncpg
```

```env
DATABASE_URL=postgresql+asyncpg://user:password@localhost:5432/tgbot
```

## Как работает доступ

Бот **не может сам добавить** человека в канал: в Bot API такого метода нет (добавлять умеют только пользовательские аккаунты, а это нарушает правила Telegram и ведёт к блокировке). Поэтому используется штатная схема:

1. Пользователь оплачивает тариф в Stars.
2. Бот создаёт **персональную одноразовую ссылку** (`member_limit=1`) со сроком жизни `INVITE_TTL_HOURS`.
3. Пользователь нажимает «🔑 Войти в канал» и вступает — один клик.
4. По истечении срока бот делает `banChatMember` → `unbanChatMember`: удаляет из канала и сразу снимает бан, чтобы после продления человек мог вернуться по новой ссылке.

Ссылки от прошлых подписок автоматически отзываются, чтобы ими нельзя было воспользоваться повторно.

## Логика подписок и платежей

- **Продление суммирует срок:** `expires_at = max(now, текущий срок) + duration_days`. Старая подписка получает статус `extended`, её остаток переносится в новую.
- **Продление без повторного входа:** если пользователь уже в канале, новая ссылка не выдаётся — приходит «Подписка продлена».
- **Идемпотентность платежей:** уникальный индекс `(provider, provider_payment_id)` плюс проверка статуса заказа. Повторная доставка события от Telegram не продлевает подписку второй раз.
- **Проверка цены:** в `pre_checkout_query` сумма сверяется с актуальной ценой тарифа; при расхождении оплата отклоняется.
- **Grace period:** при `GRACE_HOURS > 0` доступ сохраняется ещё N часов после окончания — удобно, чтобы не выкидывать человека в момент продления.
- **Напоминания:** два непересекающихся окна (от 1 до 3 суток и меньше суток), флаги в БД исключают дубли.
- **Планировщик:** проверка истечений каждые 5 минут, напоминания раз в час. Состояние хранится в БД, перезапуск бота ничего не ломает.

## Деплой на сервер

Минимальный VPS: 1 vCPU, 2 ГБ RAM, 20 ГБ SSD.

```bash
cd /opt
git clone <ваш-репозиторий> tgbot
cd tgbot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
nano .env
python -m bot.main
```

Автозапуск через systemd — `/etc/systemd/system/tgbot.service`:

```ini
[Unit]
Description=Telegram subscription bot
After=network.target

[Service]
WorkingDirectory=/opt/tgbot
ExecStart=/opt/tgbot/.venv/bin/python -m bot.main
Restart=always
RestartSec=5
EnvironmentFile=/opt/tgbot/.env
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now tgbot
sudo journalctl -u tgbot -f      # логи
```

## Публикация на GitHub

Перед публикацией убедитесь, что секреты не попали в репозиторий.

```bash
git init
git add .
git status          # .env не должен быть в списке
git commit -m "Telegram subscription bot"
git branch -M main
git remote add origin https://github.com/<user>/<repo>.git
git push -u origin main
```

В `.gitignore` уже исключены `.env`, `data/`, `.venv/`, `__pycache__/`.

Проверка вручную:

```bash
git ls-files | findstr ".env"        # Windows
git ls-files | grep "\.env"          # Linux/macOS
```

В выводе должен быть только `.env.example`.

> Если токен когда-либо попадал в коммит — считайте его скомпрометированным: перевыпустите у @BotFather (`/revoke`) и обновите `.env`. Удаление файла из истории git не отменяет утечку.

## Частые ошибки

| Ошибка | Причина и решение |
|---|---|
| `BOT_TOKEN не задан` | не заполнен `.env` или файл лежит не в корне проекта |
| `TelegramUnauthorizedError: Unauthorized` | неверный токен — скопируйте заново из @BotFather |
| `Bad Request: chat not found` | неверный `CHANNEL_ID` или бот не добавлен в канал |
| `⚠️ Не хватает прав: «Приглашать по ссылке»` | включите права бота в канале (шаг 4) |
| `Не удалось создать ссылку` | бот не админ канала или канал удалён |
| Бот не реагирует на команды | процесс не запущен или упал — смотрите лог |
| Админ-команды молчат | ваш ID не в `ADMIN_IDS`; узнайте через `/myid` и перезапустите |
| `ModuleNotFoundError: No module named 'bot'` | запускайте из корня проекта: `python -m bot.main` |
| `ImportError: greenlet` | `pip install "sqlalchemy[asyncio]" greenlet` |
| Дубли напоминаний | запущено два процесса бота одновременно — оставьте один |
| Не приходит оплата | проверьте, что бот не заблокирован пользователем, и смотрите `pending_update_count` в `getWebhookInfo` |

Диагностика в любой момент:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/getMe"
curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"
```

## Про Stars

- Оплата идёт в Telegram Stars; провайдер не нужен, `provider_token` пустой, `currency=XTR`.
- Цена в Stars — целое число больше нуля (минимум 1 ⭐).
- Вывод заработанных звёзд — через [Fragment](https://fragment.com): @BotFather → Your Bots → Payments.
- Возвраты Stars выполняются вручную через поддержку Telegram/Fragment; команда `/revoke` только снимает доступ и удаляет из канала.
